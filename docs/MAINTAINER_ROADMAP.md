# 维护路线图（独立 Fork）

> 维护对象：`EricMega/apple-store-inventory-monitor`。基线：上游 `suversal/apple-store-inventory-monitor` v1.0.22（`7f9e86d`）。当前优先支持中国大陆 Apple Store 自提库存监控和自动提交订单，付款始终由用户本人完成。

## 工程约束

- **安全优先**：未明确确认目标型号/SKU、数量、门店、允许金额时，停止自动结账。网页结构变更默认视为 `UNKNOWN`，而不是成功或无货。
- **防重复提交**：任何订单提交动作最多尝试一次。超时、进程中断或状态不明时，不能自动再次点击「立即下单」。
- **隔离部署**：建议独立 VM、单独 Apple 购物账户；不访问宿主机的浏览器资料和 iCloud 钥匙串。
- **分支策略**：一个任务一个 commit，先说明根因和验收标准，所有改动通过 PR，主分支只合并通过验证的变更。不要在自动下单期间热更新。
- **测试约束**：默认单测/CI/端到端测试绝不提交真实订单、绝不付款；真实站点的试跑仅能进入「查看订单」页，任何真实下单需使用者另行明确授权并自行执行。
- **上游同步**：定期人工审查上游新提交及依赖变动；不直接自动合并到稳定分支。保留 GPL-3.0 的许可证与来源说明。
- **信息最小化**：Cookie、订单号、电话号码、证件后四位、Bark Key 不进入 CI 日志或诊断文件。

## P0（先完成，再开启无人值守订单提交）

| 任务 | 目标 | 验收 |
| --- | --- | --- |
| 购物袋数量确定性 | 购物袋无法确认数量为 1 时终止，查看订单页可沿用此前严格核对 | 未知数量拒绝、1 件通过、2 件拒绝的自动化测试（PR #1） |
| 提交前防误购 | 商品型号/SKU、数量、门店、最高总金额独立核对，任一未知值拒绝 | 模拟不同 SKU、门店、金额和页面结构变化 |
| 持久化防重复订单 | 提交前写入意图锁，重启后 `UNKNOWN` 不再自动提交，人工核对后解锁 | 点击前后、返回前后、落盘前的崩溃注入测试 |
| 库存结果可信度 | `IN_STOCK`、`OUT_OF_STOCK`、`UNKNOWN/BLOCKED/STALE` 分开处理，仅确切且及时的有货结果触发结账 | 403/429/503/541、缺 SKU/门店、缓存过期、未授权页面等 fixture 测试 |

## P1（稳定性和安全加固）

1. **端到端演练**：以脱敏的 Apple 页面 fixture 执行从库存事件到查看订单的完整流程；手工 macOS VM 试跑需记录平台与版本。
2. **无人值守健康检查**：查询成功时间、连续错误、Chromium 重启、Bark 投递失败等事件记录，并采用去重告警；重启只自动恢复库存监控。
3. **Chromium 调试端口**：保持回环地址、随机端口；进一步审查本机其他进程可访问的风险，必要时限制持久登录会话的生命周期。
4. **配置/日志保密**：测试权限 700/600、日志脱敏、分离诊断输出；优先本地加密存储适合保密的数据。
5. **发布和 CI 门禁**：Rust fmt/clippy/test、TypeScript/前端测试、多平台打包；固定可复现依赖、验证更新签名与工件来源。

## P2（性能和体验）

- 合理复用一次 Apple 返回的多门店库存信息，按 SKU+门店严格检查覆盖范围。
- 使用合理轮询和指数退避；不把 Apple 临时错误标记为缺货。
- 提供每轮查询耗时、错误类型、最新可信库存时间、订单状态追踪。
- 支持门店优先级，但只能在用户明确允许的门店集合中选择。

## 维护节奏和验收门禁

1. 先记录可复现问题与根因，形成最小 PR。
2. PR 触发 CI，未验证时保持 Draft。
3. 程序涉及 Apple 页面的改动，先跑 mock/fixture 再在隔离 VM 上非提交试跑。
4. 只有 CI 和对应场景的回归检查通过，才能合并与发布版本。
5. 每次发版记录上游基线、变更摘要、已知问题、对应测试结果和回退路径。
